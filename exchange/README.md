# Quite Harbor — ф'ючерсна криптобіржа (в стилі Binance Futures)

USDT-M безстрокові ф'ючерси на 20 монет: лонг і шорт з плечем до 100x, ізольована маржа,
ціна маркування, ліквідації зі страховим фондом, книга ордерів і матчинг, лімітні / ринкові /
post-only / reduce-only ордери, позиції з PnL і ROE, історія, свічковий графік з історією
Binance — і все оновлюється в реальному часі. Розрахована на сотні одночасних користувачів.

## Як працюють ф'ючерси тут

- **Позиція** по кожній парі одна (one-way): лонг (ставка на зростання) або шорт (на падіння).
  Протилежний ордер зменшує, закриває або перевертає позицію.
- **Плече** 1–100x для BTC/ETH, 1–50x для інших; змінюється, коли по парі немає позиції й ордерів.
- **Маржа ізольована**: під позицію відкладається `вартість / плече`; більше за неї втратити не можна.
  Лімітні ордери блокують маржу (і запас на комісію) одразу, ринкові — перевіряються перед виконанням.
- **PnL** рахується від **ціни маркування** (середня ціна Binance, без брокера — остання угода).
  Реалізований PnL зараховується в гаманець при зменшенні/закритті позиції.
- **Ліквідація**: коли `маржа + нереалізований PnL ≤ 0.5% вартості позиції`, ордери по парі
  скасовуються, позиція закривається в книгу (до 10% від ціни маркування), залишок — у страховий
  фонд за ціною маркування. Залишок маржі йде у страховий фонд, а збиток понад маржу покриває він же.
- **Комісія** maker/taker 0.1% від вартості угоди, в USDT.
- Фандинг (періодичні виплати між лонгами й шортами) поки не реалізовано.

**Без жодних залежностей** — лише Node.js ≥ 22.5 (вбудовані `http`, `crypto`, `node:sqlite`).

## Запуск

```bash
cd exchange
npm start            # http://localhost:8080
npm test             # тести движка (вкл. ліквідації і fuzz на 6000 операцій) і брокера (мок Binance Futures)
npm run loadtest -- http://localhost:8080 100 30   # 100 користувачів × 30 секунд
```

Docker:

```bash
docker build -t quite-harbor . && docker run -p 8080:8080 -v quite-harbor-data:/data quite-harbor
```

Новий користувач отримує демо-маржу **10 000 USDT**, кнопка «Поповнити» дає
+1000 USDT раз на годину. Вбудовані боти (маркетмейкер і тейкер) тримають ліквідність у стакані
й рухають графік — вимикаються `BOTS=0`.

## Брокер ліквідності (Binance) і дублювання угод

```bash
BROKER=binance BINANCE_API_KEY=... BINANCE_API_SECRET=... ADMIN_TOKEN=... npm start
```

- **Ціни, ціна маркування й історія графіка** — з ф'ючерсного ринку Binance (`fapi.binance.com`,
  без ключів). Якщо він недоступний з вашої мережі, автоматично беруться спотові ціни Binance.
  Маркетмейкер котирує навколо них, тож ціни на біржі йдуть за світовим ринком.
- **Дублювання позицій.** Кожна угода реального користувача (боти не враховуються) змінює чисту
  позицію клієнтів по парі. Раз на секунду ця зміна відправляється ринковим ордером на
  **демо-рахунок Binance Futures Testnet**. Користувач відкрив лонг 0.01 BTC — біржа купує 0.01 BTC
  у брокера; відкрив шорт — продає.
  - Угоди згортаються (неттінг): якщо за секунду один купив 0.02, а інший продав 0.005, брокеру піде 0.015.
    Так ми не впираємось у ліміти API. Угода користувача з користувачем позицію не змінює.
  - Дрібні угоди нижче мінімуму брокера (5 USDT) не губляться, а чекають, поки набереться мінімум.
  - Захист від дублів: намір записується в БД до відправки, кожен ордер має унікальний `clientOrderId`.
    При обриві зв'язку статус перевіряється в брокера. Після рестарту стан відновлюється з БД.
  - Якщо брокер відхилив ордер (наприклад, бракує демо-коштів), кількість повертається в чергу
    і відправляється знову через 15 с.
- **Адмінка** `/admin.html` (вхід по `ADMIN_TOKEN`): ціни брокера, чиста позиція клієнтів,
  що вже захеджовано і що в черзі (звірка ✓/✗), ордери в брокера, баланс демо-рахунку, аудит біржі.
- Ключі для демо: https://testnet.binancefuture.com → зареєструватись → *API Key*.
- Захист від реальних грошей: якщо `BINANCE_TRADE_URL` не тестнет, сервер не стартує
  без явного `BROKER_ALLOW_LIVE=1`.
- Інший брокер підключається реалізацією тих самих методів, що в `src/broker/binance.js`.

Перевірено на мок-сервері Binance з перевіркою HMAC-підпису (`test/broker.test.js`): неттінг,
накопичення дрібних угод, обрив з'єднання, відмова брокера, рестарт. Наскрізний прогін: 100
користувачів × 25 с, 4716 угод, позиція клієнтів захеджована точно до 0.00001 BTC.

## Бета на власному комп'ютері (публічна адреса без хостингу)

Найшвидший спосіб дати людям потестувати: біржа працює на вашому комп'ютері, а безкоштовний
Cloudflare Tunnel дає їй адресу `https://<випадкові-слова>.trycloudflare.com`, доступну з будь-якого
місця. Роутер, порти, домен і реєстрація в Cloudflare не потрібні.

1. Встановіть **Node.js LTS** з https://nodejs.org (Windows / macOS / Linux).
2. Завантажте код: на GitHub → *Code* → *Download ZIP*, розпакуйте.
3. Відкрийте папку `exchange` і запустіть:
   - **Windows:** подвійний клік `start-beta.bat`
   - **macOS:** подвійний клік `start-beta.command` (вперше: правий клік → *Відкрити*)
   - **Linux:** `sh start-beta.command`
4. У вікні з'явиться адреса для користувачів, посилання на адмінку і її пароль. Адреса також
   зберігається у `beta-url.txt`.

Скрипт `beta.js` сам завантажує `cloudflared` (один раз), створює `beta.env` з налаштуваннями
(пароль адмінки генерується випадково, ключі Binance вписуються туди ж) і перезапускає біржу
та тунель, якщо щось упало.

Що треба знати:
- Комп'ютер має бути увімкнений і не засинати, а вікно — відкрите.
- **Адреса змінюється після кожного перезапуску**, тож після перезапуску надішліть користувачам нову.
- Швидкий тунель Cloudflare не пропускає стрім (SSE), тому сторінка за кілька секунд сама
  переходить на оновлення раз на секунду. На VPS стрім працює й оновлення миттєві.
- Ззовні відкритий лише порт біржі через тунель, і сервер слухає тільки `127.0.0.1`. Адмінка
  з інтернету відкривається тільки з паролем `ADMIN_TOKEN`.
- Дані користувачів зберігаються у `data/futures-beta.db` на вашому комп'ютері. Пізніше цей файл можна
  перенести на VPS.

## Розгортання на сервері (окремий піддомен)

Потрібен VPS (від 1 vCPU / 1 ГБ RAM) з Ubuntu/Debian і A-запис піддомену (наприклад
`exchange.medluxlife.com`) на його IP. Сайт WordPress при цьому ніяк не зачіпається.

```bash
git clone <repo> && cd <repo>/exchange/deploy
cp .env.example .env && nano .env      # DOMAIN, ADMIN_TOKEN, ключі Binance
sh install.sh                          # ставить Docker, піднімає біржу + HTTPS (Caddy / Let's Encrypt)
```

Дані зберігаються в Docker-томі `exchange-data` (SQLite). Оновлення: `git pull && docker compose up -d --build`.

## Можливості

| | |
|---|---|
| Пари | BTC/USDT, ETH/USDT (додаються в `src/config.js`) |
| Ордери | `LIMIT` (GTC / IOC / FOK), `MARKET` (за кількістю або на суму в USDT), `LIMIT_MAKER` (post-only) |
| Матчинг | пріоритет ціна → час, часткові виконання, виконання за ціною мейкера з поверненням різниці |
| Захист | блокування коштів під ордер, self-trade prevention, захист ринкового ордера від прослизання (5%), мін. сума ордера, крок ціни/кількості, ліміт 200 відкритих ордерів |
| Комісії | maker 0.1% / taker 0.1% (беруться з отриманої монети, як на Binance) і йдуть на системний рахунок `fees` |
| PnL | середня ціна входу, реалізований і нереалізований PnL, сплачені комісії, загальний капітал |
| Real-time | SSE-стрім: стакан, угоди, тікери, власні ордери, баланси і PnL |
| Графік | свічки 1m / 5m / 15m / 1h / 4h / 1d, обсяги, перехрестя, зум колесом миші |
| Безпека | scrypt-хеші паролів, HttpOnly + SameSite=Strict cookie, rate limiting (IP і користувач), CSP, ліміт розміру запиту |

## Архітектура

```
браузер ──HTTP (REST)──▶ server.js ──▶ engine.js (книги ордерів у пам'яті)
        ◀──SSE стрім────            └──▶ SQLite (WAL): кожна команда = 1 транзакція
```

- **Движок однопотоковий** (як у більшості реальних бірж): кожен ордер обробляється
  повністю й атомарно, гонок між користувачами немає за побудовою.
- **Гроші — тільки цілі числа** (BigInt, 8 знаків після коми). Крок ціни × крок кількості
  підібрані так, що `ціна × кількість` завжди ділиться без залишку — жодних похибок float.
- **Надійність**: результат кожної команди записується в SQLite однією транзакцією *до* відповіді
  клієнту. Після рестарту стан (баланси, відкриті ордери, свічки) відновлюється з БД.
  Якщо запис на диск не вдався — процес зупиняється (fail-fast), а не продовжує з розбіжністю.
- **Аудит** `GET /api/audit` (тільки з localhost або з заголовком `X-Admin-Token`) перевіряє, що
  сума всіх балансів = сума всіх депозитів, заблоковані кошти = потреби відкритих ордерів,
  стакан не перехрещений.
- Розсилка в стрім пакетується раз на 100 мс і серіалізується один раз на всіх підписників.

користувач тримає відкритий стрім і торгує з паузами 50–400 мс (ліміти, ринкові, скасування, PnL).

| Користувачів | Запитів/с | Ордерів/с | p50 | p95 | p99 | Аудит |

## API

Авторизація: cookie `sid` (браузер) або `Authorization: Bearer <token>` (токен повертається з
`/api/register` і `/api/login`). Тіла запитів — JSON, числа передавайте рядками (`"0.015"`).

| Метод | Шлях | Опис |
|---|---|---|
| POST | `/api/register` `{username, password}` | Реєстрація + демо-баланс |
| POST | `/api/login` / `/api/logout` | Вхід / вихід |
| GET | `/api/me`, `/api/balances`, `/api/pnl` | Акаунт, баланси, PnL |
| POST | `/api/order` | `{symbol, side: BUY\|SELL, type: LIMIT\|MARKET\|LIMIT_MAKER, price, qty, quoteQty, tif: GTC\|IOC\|FOK}` |
| DELETE | `/api/order?id=` / `/api/orders?symbol=` | Скасувати ордер / всі ордери |
| GET | `/api/orders/open`, `/api/orders/history`, `/api/my-trades` | Мої ордери й угоди |
| POST | `/api/faucet` | Поповнити демо-USDT |
| GET | `/api/markets`, `/api/ticker`, `/api/depth?symbol=`, `/api/trades?symbol=`, `/api/klines?symbol=&interval=` | Ринкові дані |
| GET | `/api/stream?symbol=` | SSE: `depth`, `trades`, `tickers`, `account`, `order`, `myTrade` |

Приклад:

```bash
TOKEN=$(curl -s -H 'Content-Type: application/json' -d '{"username":"bob","password":"secret1"}' \
  localhost:8080/api/register | jq -r .token)
curl -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"symbol":"BTCUSDT","side":"BUY","type":"LIMIT","price":"59000","qty":"0.01"}' localhost:8080/api/order
```

## Налаштування (змінні оточення)

| Змінна | За замовчуванням | |
|---|---|---|
| `PORT`, `HOST` | `8080`, `0.0.0.0` | |
| `DB_FILE` | `data/exchange.db` | |
| `BOTS` | увімк. | `0` — вимкнути ботів |
| `MAKER_FEE_BPS`, `TAKER_FEE_BPS` | `10` | комісія в б.п. (10 = 0.1%) |
| `TRUST_PROXY` | — | `1` за nginx/Cloudflare — брати IP клієнта з `CF-Connecting-IP` / `X-Forwarded-For` для лімітів. Запити з такими заголовками ніколи не вважаються локальними |
| `COOKIE_SECURE` | — | `1` при HTTPS |
| `ADMIN_TOKEN` | — | вхід в `/admin.html`, `/api/audit` і `/api/admin/broker` ззовні |
| `BROKER` | — | `binance` — підключити брокера ліквідності |
| `BINANCE_API_KEY`, `BINANCE_API_SECRET` | — | ключі демо-рахунку (без них — лише ціни) |
| `BINANCE_TRADE_URL` | `https://testnet.binancefuture.com` | куди йдуть ордери (ф'ючерсний тестнет) |
| `BINANCE_PRICE_URL` | `https://fapi.binance.com` | звідки беруться ціни ф'ючерсів |
| `BINANCE_SPOT_PRICE_URL` | `https://data-api.binance.vision` | запасне джерело цін |
| `MAINTENANCE_MARGIN_BPS` | `50` | підтримуюча маржа (50 = 0.5%) |

Для nginx перед сервером вимкніть буферизацію стріму (`proxy_buffering off;` для `/api/stream`;
сервер також шле `X-Accel-Buffering: no`).

## Що далі (для реальних грошей цього ще недостатньо)

Це демо-біржа з віртуальними коштами. Перед роботою з реальними активами потрібні: депозити/виводи
(гаманці, підтвердження в блокчейні), KYC/AML, 2FA, адмінка, резервне копіювання та реплікація БД,
незалежний аудит безпеки і юридичне оформлення. Для масштабу в тисячі користувачів — винести
матчинг в окремий процес на кожну пару і розсилку через Redis/NATS, а API — горизонтально.
